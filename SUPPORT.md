# Support

## Questions, Bugs, and Requests

Each harmflow repository tracks its own issues. Open an issue in the repository the request concerns:

| Concern | Tracker |
|---|---|
| The daemon, the desktop, the installers, and their tests | [`harmflow/harmflow-app`](https://github.com/harmflow/harmflow-app/issues/new/choose) |
| The public product website — its pages, content, and deployment | [`harmflow/harmflow-site`](https://github.com/harmflow/harmflow-site/issues/new/choose) |

`harmflow-app` and `harmflow-site` are public: anyone can read their issues. GitHub Discussions are not enabled.
Specifications, ADRs, and decisions are kept privately and are never cited from a public repository; a problem in a
public repository's own documentation (its README or guides) is filed in that repository.

- **Bugs** — use the *Bug report* form.
- **New capabilities or improvements** — use the *Feature request* form.
- **Questions and troubleshooting** — blank issues are disabled, so use the closest form and add the `question`
  label.

Search existing issues first. When a request spans repositories, open one issue in each and link them in full form
(`harmflow/harmflow-site#42`).

## Repository-Specific Help

Each repository's `README.md` and `CLAUDE.md` describe how to build, run, and test it.

## Security

Never report a vulnerability in an issue, discussion, or pull request. Follow the private process in
[`SECURITY.md`](SECURITY.md).
